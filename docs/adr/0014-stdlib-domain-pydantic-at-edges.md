# The domain uses only the standard library; Pydantic lives at the edges

`bank.domain` imports nothing outside the standard library (an `import-linter` contract): value objects are frozen dataclasses (`Money`, ids) and aggregates are plain classes with behaviour. Pydantic is used only where untrusted data enters or a boundary is crossed — MCP tool arguments (generated by an LLM, the system's largest untrusted input), Scenario and Bank Snapshot JSON, settings, and structured outputs from the Simulated User. This keeps the domain that `evaluation` imports dependency-free and puts validation where it actually protects something, at the cost of small mapping code in the MCP server and snapshot serialization.

## Considered Options

- **Pydantic everywhere**: one modelling tool and free serialization, but couples the domain to a library and makes behaviour-rich aggregates and state machines awkward inside `BaseModel`.
